一只分层绘制的鹈鹕嘴里叼着鱼，在路上骑自行车。鱼绑在四根骨头的脊柱上，一直在甩动。轮胎是软环，只在接触路面和石头的地方压平。每条腿是一张加权网格，通过双骨 IK 跟随旋转曲柄上的踏板。翅膀是绑在两根骨上的一张网格，翼尖通过 IK 扶住车把。全部 26 个图层由本目录下的确定性脚本生成，不需要下载素材、付费编辑器或游戏资源。

案例跑通了 [skin-weights](../../skills/2d/skin-weights/SKILL.md) 的完整流程，并展示权重出错的几种方式：翻折、像橡皮一样弯曲、接缝。

## 运行

```sh
python -m pip install -r requirements-dev.txt
python examples/pelican-bicycle/run.py --out /tmp/pelican-review
python examples/pelican-bicycle/make_figures.py --run /tmp/pelican-review   # 可选：重建 docs/ 插图
```

只有两种预期结果都复现时，`run.py` 才以 0 退出。完整运行会渲染 GIF，需要几分钟；只要报告可加 `--no-render`。

## 嘴里的鱼

<p align="center">
  <img src="docs/fish.gif" alt="绑定四骨脊柱的鱼在鹈鹕的喉囊里甩动" width="560"/>
</p>

鱼夹在两个刚性图层之间：喉囊内壁在它后面，带喉囊边缘的喙在它前面，所以看起来是被叼住的。四根骨头构成行进的尾波（两秒三次摆尾），路面颠簸会再叠加一次翻滚和一次跳起。权重过渡很宽，因为鱼本来就该整条身体都是软的。每个关节的过渡带约 3 个单位宽，没有任何三角形翻折。

## 扶着车把的翅膀

翅膀画成一条手臂：上段是成排的覆羽，下段是深色飞羽组成的“手”，绕着车把握把卷起来。两段是同一张网格，绑在 `wing` 和 `wing_hand` 两根骨上，弯折处在腕部。双骨 IK 让翼尖始终落在握把上。鹈鹕在弹簧上起伏、车身压过石头俯仰时，肘角在 34° 到 39° 之间变化，翼尖与车把的误差在 2e-14 世界单位以内。

## 轮胎与路面

<p align="center">
  <img src="docs/wheel.gif" alt="后轮压过两块石头时被压扁" width="480"/>
</p>

- **软轮胎。** 轮胎是一个环形网格。内圈钉在不旋转的轮胎中心骨上，所以永远不会压进轮辋。胎面跟随外缘内侧的 24 根零长度骨。带辐条的轮辋是画在轮胎后面的独立刚性图层，在轮胎中空处转动。
- **接触。** 每一帧里，胎面按真实地面裁切：沿每根胎面骨的射线方向，轮胎落到路面或石头以下的部分被推回表面，最多 2.4 个单位，即胎壁厚度的一半。压入量沿圆周平滑一次，所以石头压出的是圆滑凹陷，而不是台阶。所以只有底部压成接地面并贴合石头形状，其余部分保持圆形。接地面旁边的胎侧按压入量的 0.25 轻微外鼓。平路上有 0.45 个单位的静态下沉，表现承重。
- **骑行。** 车身抬升刚性车轮应爬高度的 75% 并随之俯仰，鹈鹕骑在弹簧上（4.5 Hz、阻尼 0.22），会有过冲。鱼的跳动由这个加速度驱动。
- **踢飞。** 每个车轮压到最大那块石头时会向后踢出一粒小石子，平时小石子藏在路面后面。
- **无缝循环。** 路面周期正好是轮胎转一圈的长度，所以每秒滚动一个周期与车轮转动吻合。弹簧在频域里求解，最后一帧与第一帧完全相等。

## 结果

| 权重 | 静态检查 | 翻折审计 | 可见翻折像素 |
|---|---|---|---|
| 调和权重，声明刚性区 | 通过 | 通过 | 0 |
| 最近骨刚性绑定（对照组） | 失败 | 失败 | 后轮 323，前轮 329，近侧腿 198，远侧腿 164，鱼 6 |

- 即使车身起伏、俯仰（最高 2.1 个单位、±2.5°），两只脚踝仍贴在踏板上，翼尖仍扶在车把上，误差都在 2e-14 以内，IK 始终没有超出可达范围。
- 胎面最多压入 1.5 个单位，没有翻折，轮辋边缘始终不动。轮胎最小的三角形在接地面内，保留 26% 的装配面积。
- 近侧膝关节在 44° 到 114° 之间摆动，最小三角形保留 39%，小腿保持笔直（软段占比 0.05）。鱼按设计是软的（0.15 到 0.58）。

## 这个案例沉淀下来的经验

- **通过审计不等于好看。** 早期版本把脚放在腿的网格里，两端用对称的 30% 过渡带。翻折审计顺利通过，但细小腿像橡皮一样弯进脚踝。修法是把脚改成画好踝部圆球盖住的刚性图层，膝部过渡用不对称 inset 挪到大腿一侧。`pose_trace.py` 会按骨报告 `softLengthFraction`，让这个问题可以被量化。
- **接缝在动起来之前就被拦下。** 所有腿骨共用同一个 handle 半径时，小腿和脚的刚性区挨在一起，审计在那个脚踝发现了翻折。现在静态的接缝检查不跑动作就能拒绝这种配置。
- **滚动的世界要固定视窗。** 滚动背景比画面宽，按全部顶点自适应的相机会被拉远。`render_skin.py --view x0,y0,x1,y1` 可以固定世界窗口。
- **对照组证明检查有效。** 同样的网格换成最近骨刚性绑定后会翻折，静态检查和审计都会拒绝。
- **导出经过验证，不是假设。** `export_rigc.py --verify-rigc` 用 rig-c 2.79.0 编译该骨架，并用 rig-c 自己的求值器摆姿。26 个图层与本求值器的偏差：角色部分在 2e-5 世界单位以内，200 单位宽的背景在 7e-4 以内（float32 精度）。IK 被烘焙为关键帧。路面和云的轨迹在循环点归零，所以在最后两个关键帧之间做插值的引擎会出现一帧跳变。Spine 官方编辑器与解析器的往返验证未执行。
